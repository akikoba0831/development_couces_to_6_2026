## 1. 目的

### 1.1 アプリの目的
授業ごとに「楽単度」「課題量」を★で評価し、ひとこと感想を投稿できる掲示板を作る。履修を決めるときの参考にする。

### 1.2 このお題を選んだ理由（講座の目的）
- 個人で、認証・DB 設計・フォルダ構成・実装・テスト・README までを一通り経験する
- 1 対多の関係と、集計（平均）、認証・認可が自然に出てくる
- 1 画面ずつ作れるので、進捗が見えやすい

### 1.3 想定ユーザー
大学の授業を履修する学生。アカウントを作ってログインし、投稿する。

---

## 2. スコープ

### 2.1 やること
- 新規登録、ログイン、ログアウト
- 授業の一覧、詳細の閲覧
- 授業へのひとこと投稿（★評価 + コメント）
- 自分の投稿の編集・削除
- 授業ごとの平均★の表示

### 2.2 やらないこと（時間が溶けるため、今回は対象外）
- スターターキット（Breeze など）の利用。認証は Laravel 標準の機能で自分で作る
- パスワードリセット、メール認証
- 授業の編集・削除（登録のみ）
- 禁止ワード対策、通報機能
- 外部 API、画像アップロード
- 本番環境へのデプロイ
- レスポンシブ対応（PC 表示のみ）

## 3. 画面と機能（1 画面 1 タスク）

優先度：**必須**（これだけは作る）／**推奨**（余裕があれば）／**挑戦**（早く終わった人向け）

| ID | 画面 | この画面のタスク | パス | 優先度 |
|---|---|---|---|---|
| S1 | 新規登録 | 名前・メール・パスワードでアカウントを作る | `GET/POST /register` | 必須 |
| S2 | ログイン | ログイン、ログアウトができる | `GET/POST /login`、`POST /logout` | 必須 |
| S3 | 授業一覧 | 授業を平均★つきで並べる | `GET /courses` | 必須 |
| S4 | 授業詳細 | 授業の情報と、ひとこと一覧を見る | `GET /courses/{id}` | 必須 |
| S5 | 投稿作成 | ひとことを投稿する | `GET/POST /courses/{id}/reviews/create` | 必須 |
| S6 | 投稿編集 | 自分の投稿を直す、削除する | `GET/PUT/DELETE /reviews/{id}` | 推奨 |
| S7 | 授業登録 | 授業を追加する | `GET/POST /courses/create` | 推奨 |
| S8 | マイページ | 自分の投稿だけを一覧で見る | `GET /mypage` | 挑戦 |
| S9 | ランキング | 楽単度の平均 TOP5 を見る | `GET /ranking` | 挑戦 |

> パスは目安です。Laravel の慣習（リソースルート）に沿っていれば、変えてかまいません。

### 3.1 実装の順番（おすすめ）
**S3 → S4 → S1 → S2 → S5 → S6 → S7**

先に「見るだけの画面」を作ると、早くアプリが動いて見えます。ログインが必要な画面は後に回します。

### 3.2 各画面の詳細

#### S1 新規登録
- 入力項目：名前（必須、50 文字まで）、メール（必須、重複不可）、パスワード（必須、8 文字以上、確認用も入力）
- 登録できたら、そのままログイン状態になり、授業一覧へ移動する
- ログイン済みの人が開いたら、授業一覧へ移動する

#### S2 ログイン
- 入力項目：メール、パスワード
- 失敗したら、「メールまたはパスワードが違います」を表示する（どちらが違うかは教えない）
- 成功したら、授業一覧へ移動する
- ログアウトは、ヘッダーのボタンから行う（専用の画面は作らない）

#### S3 授業一覧
- 授業のカードを並べる。表示項目：授業名、先生名、分野、楽単度の平均★、課題量の平均★、投稿数
- 投稿が 0 件の授業は、★の代わりに「まだ投稿がありません」を表示する（割り算のエラーを出さない）
- ログインしていなくても見られる

#### S4 授業詳細
- 授業の情報（授業名、先生名、分野）、平均★、投稿数を表示する
- ひとこと一覧を新しい順に表示する。表示項目：投稿者名、楽単度★、課題量★、ひとこと、投稿日
- 「ひとことを投稿する」ボタンを置く
  - 未ログインのときは、押すとログイン画面へ移動する
  - すでに投稿済みのときは、ボタンの代わりに「投稿済み」と、自分の投稿の編集リンクを表示する（S6 が未実装なら「投稿済み」のみ）
- ログインしていなくても見られる

#### S5 投稿作成
- 入力項目：楽単度（★1〜5、必須）、課題量（★1〜5、必須）、ひとこと（必須、100 文字まで）
- 投稿者は、ログイン中のユーザーが自動で入る
- 同じ授業に 2 回目の投稿はできない（エラーを表示する）
- 未ログインでは開けない（ログイン画面へ移動する）
- 投稿できたら、その授業の詳細画面へ移動し、完了メッセージを表示する

#### S6 投稿編集（推奨）
- 入力項目は S5 と同じ。もとの内容が入力済みの状態で開く
- 削除ボタンを置く（押す前に確認ダイアログを出す）
- **自分の投稿だけ**編集・削除できる。他人の投稿の URL を開いたら「403（権限がありません）」にする

#### S7 授業登録（推奨）
- 入力項目：授業名（必須、50 文字まで）、先生名（必須、30 文字まで）、分野（必須。例：情報、語学、教養）
- ログイン中の人だけが登録できる

#### S8 マイページ（挑戦）
- 自分の投稿を、授業名つきで一覧表示する。各投稿から編集画面へ移動できる

#### S9 ランキング（挑戦）
- 楽単度の平均が高い順に TOP5 を表示する。投稿が 3 件未満の授業は対象外

### 3.3 共通
- 全画面にヘッダーを置く（アプリ名、授業一覧へのリンク）
  - 未ログイン：「ログイン」「新規登録」
  - ログイン中：ユーザー名、「ログアウト」
- 入力エラーは、フォームの該当項目の近くに表示する
- 保存・削除のあとは、完了メッセージを表示する

### 3.4 その他の挑戦課題（画面追加なし）
- **「参考になった」ボタン**：ひとことに 👍 をつけ、回数を表示する（ユーザー ⇔ 投稿の多対多が加わる）
- 一覧の検索（授業名・先生名）と並べ替え（楽単度が高い順、課題量が少ない順）

## 4. データ要件

### 4.1 テーブル一覧（3 テーブル）

#### users（ユーザー）

| カラム | 型 | 必須 | 備考 |
|---|---|---|---|
| id | 主キー | ○ | |
| name | 文字列 | ○ | 最大 50 文字 |
| email | 文字列 | ○ | 重複不可 |
| password | 文字列 | ○ | ハッシュ化して保存（平文で保存しない） |
| created_at / updated_at | 日時 | ○ | |

#### courses（授業）

| カラム | 型 | 必須 | 備考 |
|---|---|---|---|
| id | 主キー | ○ | |
| name | 文字列 | ○ | 最大 50 文字 |
| teacher | 文字列 | ○ | 最大 30 文字 |
| category | 文字列 | ○ | 分野 |
| created_at / updated_at | 日時 | ○ | |

#### reviews（ひとこと）

| カラム | 型 | 必須 | 備考 |
|---|---|---|---|
| id | 主キー | ○ | |
| user_id | 外部キー | ○ | users.id。ユーザー削除と一緒に削除 |
| course_id | 外部キー | ○ | courses.id。授業削除と一緒に削除 |
| easy_rating | 整数 | ○ | 楽単度。1〜5 |
| workload_rating | 整数 | ○ | 課題量。1〜5（5 が課題多め） |
| comment | 文字列 | ○ | 最大 100 文字 |
| created_at / updated_at | 日時 | ○ | |

- `user_id` と `course_id` の組み合わせは**重複不可**（1 人 1 授業につき 1 回までの投稿）

### 4.2 リレーション
- ユーザー 1 : 投稿 多
- 授業 1 : 投稿 多

### 4.3 ダミーデータ（シーダーで作る）
- ユーザー：4 人（ログイン確認用。パスワードは全員共通でよい。メールとパスワードは README に書く）
- 授業：8 件。**架空の授業・先生名にする**（例：「たのしい情報学入門」）。実在の授業・先生名は使わない
- 投稿：15 件程度。授業ごとにばらつきをもたせる（投稿が 0 件の授業を 1〜2 件、多い授業を 1〜2 件）
- 同じユーザーが同じ授業に 2 回投稿するデータは作らない

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| 技術 | PHP / Laravel（バージョンは当日の配布時に確認して記入：`TODO`） |
| 実行環境 | Docker（`docker compose`）。PHP と MySQL はコンテナの中で動かす |
| DB | MySQL（`db` コンテナ） |
| 画面 | Blade テンプレート。CSS は自由（Tailwind CDN や素の CSS など） |
| 認証 | スターターキットを使わず、Laravel 標準の認証機能で実装する |
| セキュリティ | パスワードはハッシュ化。フォームは CSRF 対策（`@csrf`）を入れる |
| テスト | Feature テストを 3 本以上（下記） |

### 5.1 テストの必須項目
1. ログインしていれば、ひとことを投稿できる（正常系）
2. ログインしていないと、投稿できない（ログイン画面へ移動する）
3. 同じ授業に 2 回投稿できない（異常系）

S6 を実装した人は、「他人の投稿は編集できない（403）」も加える。

テストは、開発用の DB とは別の DB（`rakutan_test`）で実行する。`phpunit.xml` で指定済み。テストで開発用のデータが消えないよう、AI に設定を確認させること。
